# СПЕКТР

Веб-приложение сервисного центра по ремонту электронной техники.
Клиент оформляет и отслеживает обращения, мастер работает с назначенными заказами, администратор принимает заявки, назначает мастеров и учитывает оплату.

**Технологии:** PHP 8.2+, PostgreSQL 14+, HTML, CSS, JavaScript. Дополнительные библиотеки не требуются.

## Запуск

Для запуска нужна установленная PostgreSQL и PHP с расширением `pgsql`. XAMPP подходит, но MySQL для этого проекта не используется.

1. Создайте пустую базу PostgreSQL `spektr` с владельцем, у которого есть право создавать таблицы
2. Выполните в ней `sql/schema.sql`, затем `sql/seed.sql` (только в новой пустой учебной базе)
3. В XAMPP откройте `C:\xampp\php\php.ini` и включите `extension=pgsql`, если оно отключено
4. Скопируйте `config.example.php` в `config.php` и укажите адрес, порт, название БД, пользователя и пароль
5. В Windows откройте `ЗАПУСТИТЬ_САЙТ.bat`. Сайт откроется по адресу http://127.0.0.1:8000

Для ручного запуска откройте терминал в папке проекта:

```bat
C:\xampp\php\php.exe -S 127.0.0.1:8000 -t public
```

Папка `public` является корнем сайта. Apache и MySQL для локального запуска не нужны. Окно терминала нельзя закрывать, пока работает сайт.

**Если база уже развёрнута на сервере команды:** повторно загружать `schema.sql` и `seed.sql` не надо. Укажите параметры существующей базы в `config.php`.

## Основные операции

- **Клиент:** регистрация, вход, новая заявка, выбор мастера, история ремонтов, отображение цены и оплаты, льготы, ваучеры, промокоды и отзывы
- **Мастер:** профиль, свои назначения, изменение статусов, учёт выполненных работ
- **Администратор:** приём и отказ с причиной, назначение по специализации, заказы, клиенты, техника, запчасти, скидки, оплата и сводка

Оплата в приложении **учётная**: администратор фиксирует факт оплаты. Прямое списание с банковской карты и реальная отправка чеков через внешнюю платёжную систему не реализованы.

Выбранный клиентом мастер сохраняется в примечании истории заказа до подтверждения администратором. Первоначально выбранная услуга записывается в описание обращения. Это связано с тем, что в утверждённой таблице `repair_orders` нет отдельных столбцов для этих двух параметров.

**Подбор мастера:** даже для общей диагностики требуется действующая специализация по виду устройства. Если вид работы требует дополнительной квалификации, проверяется также её уровень. В форме клиента и при назначении администратором действует одна и та же проверка. Услуги по категории «Другая техника» доступны для обращения, но назначить мастера без соответствующей специализации невозможно. В текущих тестовых данных такой специализации нет.

**Учебное упрощение для льгот:** при применении льготы тип скидки выбирается по совпадению части её названия со справочником скидок. Для промышленной системы правильнее хранить явную связь между категорией льготы и типом скидки; в утверждённой схеме такой связи нет. Не следует произвольно переименовывать льготы и скидки без проверки этого соответствия.

В `sql/schema.sql` находятся таблицы, ограничения и триггеры команды с исправленной обработкой `INSERT` в двух функциях. В `sql/seed.sql` используется заполнение команды с рабочими учебными хэшами паролей и статусами отказа/отмены для интерфейса.

## Что исправлено после проверки

- функция `pg_result()` переименована, чтобы не конфликтовать с расширением `pgsql`
- мастеру доступны его прежние завершенные заказы только для просмотра
- список заказов не ограничивается первыми 500 записями, а сводка считается запросами SQL
- отключенная учетная запись перестает действовать при следующем запросе
- завершение ремонта требует указанной выполненной работы или диагностики
- повторное назначение после завершения ремонта запрещено
- гарантийный срок проверяется по тарифу исходной работы
- исправлены поиск отзывов, форма скидки и сохранение состояния устройства при приеме
- клиент может изменить свои контактные данные в личном кабинете
- диагностические работы назначаются только мастеру по соответствующей технике
- формы добавления работ и списания запчастей скрываются после завершения ремонта
- форма изменения статуса не показывается, если для сотрудника нет допустимых переходов

**Проверка PostgreSQL после этой доработки обязательна.** В сборке проверены синтаксис PHP/JavaScript и открытие публичных страниц, но полный сценарий с PostgreSQL после этих изменений здесь не выполнялся. Перед демонстрацией требуется вновь проверить все роли и операции на чистой базе.

## Проверка перед демонстрацией

1. Войдите клиентом, откройте свою историю и отправьте заявку с выбором мастера
2. Войдите администратором, примите заявку и назначьте выбранного специалиста
3. Войдите мастером, найдите назначенный заказ, измените статус и добавьте работу
4. Войдите администратором, добавьте запчасть при наличии остатка, оформите скидку и оплату
5. Убедитесь, что оплаченный заказ можно выдать, а клиент после выдачи может оставить отзыв
6. Проверьте отказ с причиной и запрет на просмотр чужого заказа
7. Для диагностики ноутбука проверьте, что мастер только по телефонам недоступен для выбора и назначения
8. Переведите заказ в статус «Готов к выдаче» и проверьте, что формы работ, запчастей и изменения статуса у мастера скрыты

## Структура

- `public/` — страницы, стили, JavaScript, изображения
- `src/common.php` — сессии, авторизация, проверки форм
- `src/page.php` — общая разметка
- `src/repository.php` — функции для страниц
- `src/repository_pg.php` — запросы и операции с PostgreSQL
- `src/settings.php` — загрузка настроек
- `sql/schema.sql` и `sql/seed.sql` — создание и учебное заполнение БД

Пароль PostgreSQL храните только в `config.php`: он исключён из Git файлом `.gitignore`.
